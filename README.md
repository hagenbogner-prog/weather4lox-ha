# Weather4Lox HA

Home Assistant add-on that emulates the Loxone Gen 1 Weather Service on TCP port 6066. It reads the selected Home Assistant weather provider and serves the `format=2` response expected by a Loxone Miniserver.

The protocol implementation follows the architecture and field structure described by SmartHome.Exposed's Local Weather Service Emulator: DNS redirection is handled outside the add-on, the add-on keeps a local forecast cache, and the Loxone client receives a Weather4Loxone format-2 response from the local service.

Reference: https://smarthome.exposed/local-weather-service-emulator/

## Architecture

```text
Loxone Miniserver Gen 1
        |
        | weather.loxone.com -> Home Assistant via dnsmasq
        | HTTP :6066 /forecast/
        v
Weather4Lox HA add-on
        |
        | Home Assistant Supervisor API
        v
Selected HA weather entity
  ├─ OpenWeatherMap
  └─ DWD
        |
        v
local forecast cache -> Loxone format=2 serializer
```

This repository contains only the Home Assistant add-on. There is no LoxBerry plugin, LoxBerry runtime, or LoxBerry-specific JSON endpoint.

## Loxone endpoint

```text
http://HOME_ASSISTANT_IP:6066/forecast/?user=loxone_TEST&coord=10.681,48.56&asl=450&format=2&new_api=1
```

For `format=2`, the response contains:

- the 29-field `<mb_metadata>` header
- a 10-field station metadata line
- 19 fields per hourly `<station>` row
- Loxone-compatible numeric pictograms
- local date/time, timezone and UTC offset
- precipitation, probability, pressure, humidity and wind values

The add-on refreshes its local forecast cache independently of Loxone requests. The default refresh interval is 30 minutes. Loxone requests are served from the cache rather than triggering an external weather lookup.

No synthetic weather data is generated by default. If the selected provider has a shorter forecast horizon, the response contains the real provider data available through Home Assistant, with cache/daily fallback where configured.

## Weather provider selection

The add-on supports:

- `openweathermap` → `weather.openweathermap`
- `dwd` → `weather.wertingen`
- `custom` → a user-selected Home Assistant weather entity

OpenWeatherMap credentials remain managed by the Home Assistant integration; they are not stored in this add-on.

## Default location

- Wertingen, Germany
- latitude `48.56`
- longitude `10.681`
- elevation `450 m`
- timezone `Europe/Berlin`

All provider entities and location settings can be changed in the add-on configuration.

## Testing

Check that the add-on is reachable:

```bash
curl http://HOME_ASSISTANT_IP:6066/health
```

Check the Loxone-compatible response:

```bash
curl "http://HOME_ASSISTANT_IP:6066/forecast/?user=loxone_TEST&coord=10.681,48.56&asl=450&format=2&new_api=1"
```

Diagnostics are available at `/status`, `/raw`, `/debug/forecast` and `/debug/loxone/validate`.

## Development

CI compiles the Python sources, validates the Home Assistant add-on configuration, builds the Docker image and runs the test suite. The project does not create ZIP packages.
